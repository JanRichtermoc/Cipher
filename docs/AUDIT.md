# Cipher — security audit ledger

Every known weakness, accepted trade-off, and unfinished control, in one place.

This file exists because `Vendor/libsignal/DECISIONS.md` requires it, and because a security
argument that lives only in code comments cannot be reviewed as a whole. **An item is only
removed from here when the control that closes it exists and is tested.** Downgrading an item
to "probably fine" is not closing it.

Status legend: **OPEN** — unmitigated · **ACCEPTED** — understood, deliberate, compensated ·
**CLOSED** — a tested control exists.

**Columns.** *Adversary* names the section of [`THREAT_MODEL.md`](THREAT_MODEL.md) §1 the finding
matters to — a finding with no adversary is a bug, not a security finding. *Fix in* is the stable
step id in [`CLAUDE_IMPLEMENTATION_PLAN.md`](CLAUDE_IMPLEMENTATION_PLAN.md) that closes it, so the
ledger and the roadmap cannot drift apart.

**Ids are permanent and are cited from code, scripts and the other docs.** Never renumber a live
id; if two items ever collide, the more-cited one keeps the number and every citation of the other
is updated in the same commit.

**A CLOSED entry states the invariant and the guard that enforces it**, not the story of how it
was found. What matters going forward is what must stay true and what would notice if it stopped
being true. Compressed 2026-07-29; the narratives are recoverable from git history.

Last reviewed: 2026-08-04, after the P5.S11 storage-quota remediation that closed 4.14 and
recorded 4.15; before it, the integrated P5 review and the P5.S10 receive-atomicity remediation
that found 1.13.

## 0. Recurring failure modes

Four classes have each produced multiple findings. Stated once here as rules, because they were
first recorded as facts about one command and recurred anyway.

**R1 — Never put an infinite or long producer upstream of a consumer that exits early.**
(1.9, 1.10.) `head -c`, `grep -q` and `grep -m` all close the pipe; `xcodebuild` raises
`NSFileHandleOperationException` and GNU `tr` reports `write error: Broken pipe`, so under
`set -o pipefail` a *succeeding* pipeline fails the build. BSD and BusyBox variants die quietly,
so it works on macOS and alpine and fails on `ubuntu-24.04` — it passes locally and breaks in CI.
Buffer into a variable, or make the finite side the producer. **Live trap:** `verify-all.sh`'s
`xcodebuild | grep | sort -u | grep -q` pipelines are safe only because `sort -u` cannot emit
until it has read all input. Removing the `sort` in a cleanup reintroduces 1.9.

**R2 — A gate that has never been made to fail is not a gate.** (1.9, 5.12, 6.7, 6.8, 5.16.)
Four ways it has actually gone wrong here: the check scanned prose that *describes* the control
rather than the control (comments naming the very strings being forbidden — strip comments
first); the check trusted an exit code that carries no meaning (`docker compose port` exits 0
saying `invalid IP:0`); the check aborted before running and its silence was read as an
accusation; and the check was run with an instrument that cannot express the negative (macOS
`openssl` is LibreSSL and cannot drive a `-tls1_3` probe, so it reported an impossible
"1.2 refused / 1.3 refused"). Every gate in this repo is negative-tested by reintroducing the
defect. A gate that cries wolf is as dangerous as one that never fires — it gets deleted.

**R3 — `#if DEBUG` fences code, not resources.** (5.10, 5.11.) `Localizable.xcstrings` compiles
into the bundle regardless, and Xcode emits every translated `stringUnit` even for keys it drops
from `en.lproj`. Any audit of "what ships" must read the whole `.app`, not the Mach-O.

**R4 — A control removed from the source survives in its translations.** (5.4, 5.10, 5.13, 5.14.)
Deleting an English string leaves its `cs` rendering in the catalog, and a guard list written in
English silently exempts every other language ("passcode" → "kód zařízení").
`Scripts/verify-localization.py` searches every language and carries a `--self-test` that
reintroduces each defect before its own verdict is believed.

| 3.1 | **The base-key witness is a bounded FIFO (512 entries per prekey pair) and evicts rather than fails.** Anyone holding the published bundle can start a session, so it has an unauthenticated growth vector; unbounded is disk exhaustion, failing closed lets an unauthenticated party permanently disable session establishment.
